## Describe your changes

For GWDM 2.x, the SQL tables are the source of truth for linkages/publications on read. Two bugs broke that:

**1. Publication DOIs failed validation.** `Gwdm2xHandler::afterRead()` reads DOIs from `publications.paper_doi`, which is stored inconsistently (bare `10.1111/tme.12750`, `doi.org/…`, or `https://doi.org/…`). TRASER only accepts the bare form, so URL-style DOIs made `GET /api/v2/datasets/{id}?schema_model=GWDM&schema_version=2.0` fail with *"Reconstructed GWDM … failed schema validation"*. Added `normalisePublicationDoi()` to strip any `doi.org` prefix (scheme optional) and applied it in `afterRead()`.

**2. The onboarding/edit form ignored SQL.** The form hydrates via `GET /api/v2/teams/{teamId}/datasets/{id}` → `getDatasetDetails()`, which translated the **raw metadata blob** instead of reconstructing. So the form showed different linkage/publication data than the read API. `getDatasetDetails()` now reconstructs via `DatasetService::getReconstructedMetadataEnvelope()` before translating, matching the flat read path (`prepareForShow()`).

Both are read-path only — no stored data is changed.

**Follow-up (not in this PR):** normalising `publications.paper_doi` at write time / via a backfill.
